## cmp-app：从零搭建 Compose Multiplatform 工程

在 `/Users/qt/dev/cmp-app` 从空目录创建 CMP 多平台工程，用户指定 Compose 1.13 / Kotlin 2.4.21，并要求 Gradle 走腾讯云镜像。

### 版本落定
- Kotlin **2.4.21**（2026-10-08 的 bugfix 版，当前最新稳定）
- Compose Multiplatform **1.13.0-rc01**（Maven 上 1.13 线只发到 rc01，无 stable；Jetpack Compose 1.13 已 stable）
- AGP **9.2.1**（官方 compose-multiplatform 示例中与 Kotlin 2.4.20 搭配验证过的版本，支持 compileSdk 37.1 的 minorApiLevel 语法）
- Gradle **9.5.0**（wrapper 指向腾讯云分发；sha256 与官方包一致：553c78f5…）

### 结构（AGP 9 之后的定式）
- `composeApp`：KMP 库，插件组合 = kotlinMultiplatform + **com.android.kotlin.multiplatform.library** + composeMultiplatform + composeCompiler；android target 写在 `kotlin { android { … } }` 内
- `androidApp`：纯 Android 壳（com.android.application + MainActivity）
- `desktopApp` / `webApp`：jvm / wasmJs 壳
- `iosApp`：手写 pbxproj + 共享 scheme，Build Phase 调 `:composeApp:embedAndSignAppleFrameworkForXcode`

### 踩坑记录（重要，后续复用）
1. **AGP 9 不再允许 KMP 模块用 com.android.application**，必须拆成「KMP 库 + Android 壳」两个模块。
2. **composeApp 与 androidApp 的 namespace 不能相同**，否则 manifest merger 报 "Namespace used in multiple modules"。库用 `com.example.cmpapp.shared`。
3. **CMP 1.13 不再发布 iosX64 产物**，`components-ui-tooling-preview` 无 iosX64 variant，KGP 会报 "Unresolved platforms: [iosX64]"，只能保留 iosArm64 + iosSimulatorArm64。
4. `compose.desktop.currentOs` 在 1.13 已废弃，改用 `compose.desktop.common`。
5. 在 KMP 脚本里 `desktopMain.dependencies { }` 这种类型安全访问器会 Unresolved，需要 `named("desktopMain")` 或干脆把桌面依赖放到 desktopApp 模块。
6. **yarn 从 GitHub Releases 下载会超时** → `kotlin.js.yarn=false` + `kotlin.js.nodejs.download=false` 改用本机 node/npm；npm 源用腾讯云 `https://mirrors.cloud.tencent.com/npm/`。
7. 本机（沙箱环境）里 JVM 进程对 `~/.konan`、`~/Library/Android/sdk` 的 rename/unlink 会报 EPERM：AGP/KGP 自动安装组件失败后残留 `.part`、`.backup-*`、`.installer` 目录时必须先手工清干净再重跑，否则一直失败。清一次后 Android SDK 37.1 与 Kotlin/Native 工具链均安装成功。
8. 本地无 gradle，先从腾讯云镜像下载 9.5.0 发行包再 `gradle wrapper` 生成 wrapper。

- wasm：`compileKotlinWasmJs` 成功；`:webApp:build` 最终成功，产物 `webApp/build/dist/wasmJs/productionExecutable`
- Web 实机渲染用无头 Chrome + SwiftShader 截图验证通过（截图存 `docs/web-wasm.png`），页面文案/卡片/按钮全部正常

### 补充踩坑
9. **无头 Chrome 截 Compose/Wasm 页面**：默认 `--headless=new` 没有 WebGL，页面只显示 "This application requires WebGL2"；需要
   `--no-sandbox --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` 才能软渲染出真实画面。
10. **npm 安装中断会写坏共享缓存**：`~/.kotlin/kotlin-npm-tooling/npm/<hash>/node_modules` 缺包时 webpack 报
   `Cannot find module .../@jridgewell/gen-mapping`，删掉该缓存 + `webApp/build/js` 重跑即可。
11. **Bash 工具报 `sandbox-exec: data object length 68025 exceeds maximum (65535)`**：属于命令沙箱自身故障（seatbelt profile 超 64KB），
   与项目无关；约 10 分钟后自行恢复，期间未做任何修复。若再次出现，重启会话/清理 workspace 里庞大的 node_modules 树可降低触发概率。

## iOS 模拟器预览（同日晚补充）

### 环境事实
- Xcode 26.0.1，`iphoneos26.0` / `iphonesimulator26.0` SDK 都在，但 **runtime 一个没装**：
  `xcrun simctl list runtimes` 返回空，`/Library/Developer/CoreSimulator/Profiles/Runtimes` 不存在。
- 只装 Xcode ≠ 有模拟器。修：`xcodebuild -downloadPlatform iOS` 拉 iOS 26.0.1 Simulator，8.05 GB，约 3.1 MB/s（40 分钟）。
  该命令跑在沙箱里会因写不了 `~/Library/Developer/Xcode/SDKToSimulatorIndexMapping.plist` 而在 stderr 报 Code=513，
  但下载/安装本身仍 `Done.`，事后 `simctl list runtimes` 能看到 `iOS 26.0 (26.0.1 - 23A8464)` 即成功。

### 踩坑
12. **`Unknown iOS simulator arch: 'x86_64'`**：`-destination 'generic/platform=iOS Simulator'` 默认建 x86_64+arm64，
    而项目已移除 iosX64（CMP 1.13 无该产物），Kotlin Framework 只有 arm64。必须加
    `ARCHS=arm64 ONLY_ACTIVE_ARCH=YES VALID_ARCHS=arm64`。
13. **装进模拟器启动即闪退，主屏看不到窗口**：`simctl launch --console-pty` 才抓到真正原因 ——
    CMP 1.13 的 `PlistSanityCheck` 强制要求 Info.plist 有 `CADisableMinimumFrameDurationOnPhone = true`，
    缺失直接抛 `IllegalStateException`（异常发生在 dispatch 队列里，不产生 crash log，表现就是"图标在但点了没反应"）。
    已在 `iosApp/iosApp/Info.plist` 补键解决。
14. 排查"看起来启动了但界面不在前台"的经验：`simctl launch` 返回 PID 不代表 UI 起来了；要
    `simctl launch --console-pty` 看 Kotlin 异常输出，比 `log show` 有效得多。

### 产物
- `scripts/ios-sim-preview.sh`：一键 build(.app) → boot 模拟器 → install → launch → 截图，已验证可复现。
- 截图 `docs/ios-simulator.png`：标题/平台行"运行平台：iOS 26.0.1"/卡片/按钮全部正常渲染。

## 包名改为 com.dicek.app + 接入 compose-bom（17:50）

### 包名迁移
- Kotlin 包 `com.example.cmpapp` → `com.dicek.app`：8 个源集目录整体 mv 到 `com/dicek/app`，9 个 .kt 改 package 声明。
- namespace 规划保持"两者不能相同"：`composeApp` = `com.dicek.app.shared`，`androidApp` = `com.dicek.app`；
  iOS `BUNDLE_ID=com.dicek.app`；`scripts/ios-sim-preview.sh` 的 BUNDLE 同步改。
- Swift 侧 `MainViewControllerKt.MainViewController()` **不用改**：Kotlin/Native 导出到 Swift 用文件名生成类名，不含包名。
- AndroidManifest 用相对名 `.MainActivity`，跟随 namespace 自动适配，无需改。
- 验证：desktop `compileKotlinJvm --rerun-tasks` 通过；APK 重建后 `applicationId = com.dicek.app`；
  iOS 模拟器重装 `com.dicek.app` 启动渲染正常；wasm 编译通过。

### compose-bom 的关键结论
- `androidx.compose:compose-bom` 最新 **2026.11.01**（ui 1.13.0 / material3 1.5.0）。
- **不能替换 `org.jetbrains.compose.*`**：`androidx.compose.ui:ui` 的 Gradle module 只有
  android / jvmStubs / linuxx64Stubs / metadata 变体，**没有 iOS/Wasm 产物**，放进 commonMain 会让 iOS/Wasm 解析失败。
- 正确用法：BOM 只加在 `androidApp`（普通 Android 模块），作用是统一 Android 侧 androidx 传递依赖版本。
  实测把 `ui:1.10.0/1.11.0-rc01/1.12.0` 提升到 `1.13.0`，`material3:1.3.1` 提升到 `1.5.0`，与 CMP 1.13.0-rc01 内部要求一致。
- **坑**：`platform()` 扩展在 KMP 的 `sourceSets { }` 里不可用，报 `Unresolved reference 'platform'`，
  只能写在顶层 `dependencies { }`（DependencyHandlerScope）里。
